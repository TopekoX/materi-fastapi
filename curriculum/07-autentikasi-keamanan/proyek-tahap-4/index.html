    Proyek Praktik Tahap 4¶

    Tujuan pembelajaran¶

    Setelah mengerjakan halaman ini, kamu mampu:

    • Menambahkan pengguna, pendaftaran, dan login berbasis token ke proyek yang sudah berjalan.
    • Menyimpan kata sandi sebagai hash dan tidak pernah mengembalikannya.
    • Melindungi semua endpoint tugas, dan membatasi data per pemilik.
    • Menerapkan otorisasi peran (anggota dan pengelola) dan kepemilikan.
    • Menulis migrasi yang menambah tabel dan kolom berelasi pada SQLite dengan batch_alter_table.
    • Memasang CORS untuk frontend yang sah.

    Prasyarat¶

    • Sudah mengerjakan Proyek Praktik Tahap 3.
    • Sudah membaca seluruh materi Modul 07: Hashing Password, Token, Proteksi Endpoint, Otorisasi, dan CORS.

    Versi yang diuji

    Kode dan output di halaman ini dijalankan dengan Python 3.14.7, FastAPI 0.162.0, SQLModel 0.0.48, Alembic 1.20.1, PyJWT 2.15.1, dan pwdlib 0.3.1 di Windows. Daftar versi lain ada di Versi yang dipakai di materi ini. Versi lain dan sistem operasi lain belum diuji.

    Tentang tahap ini¶

    Tahap 4 melanjutkan TugasKu API. Sampai tahap 3, siapa pun bisa membaca dan mengubah semua tugas. Kini setiap tugas punya pemilik, dan hanya pemilik (atau pengelola) yang bisa mengaksesnya.

    Aspek Tahap 3 Tahap 4
    Pengguna tidak ada tabel pengguna dengan hash kata sandi dan peran
    Akses terbuka untuk semua wajib login (token Bearer)
    Tugas milik bersama punya pemilik_id
    Peran tidak ada anggota dan pengelola
    Kategori siapa saja bisa membuat hanya pengelola yang membuat
    Judul unik di seluruh tabel per pemilik
    CORS tidak ada hanya origin frontend yang diizinkan
    Kunci rahasia tidak ada SECRET_KEY dari variabel environment

    Kebutuhan¶

    Operasi Method dan path Siapa yang boleh
    Daftar POST /daftar siapa saja
    Login POST /token siapa saja
    Profil GET /saya pengguna login
    Buat kategori POST /kategori pengelola
    Daftar kategori GET /kategori pengguna login
    Buat tugas POST /tugas pengguna login (pemilik = pembuat)
    Daftar tugas GET /tugas pengguna login; anggota melihat miliknya, pengelola melihat semua
    Baca, ganti, ubah, hapus tugas /tugas/{id} pemilik atau pengelola

    Struktur proyek¶

    Kode lengkap ada di examples/fastapi/proyek/tahap-4/:

    Berkas Fungsi
    models.py Model tabel dan skema (menambah Pengguna dan pemilik_id)
    main.py Aplikasi: konfigurasi, error, autentikasi, dan endpoint
    buat_pengelola.py Skrip untuk membuat akun pengelola pertama
    alembic.ini, alembic/ Migrasi, termasuk revisi baru untuk tahap ini

    Langkah menjalankan¶

    pip install "fastapi[standard]" sqlmodel alembic pyjwt "pwdlib[argon2]"
$env:SECRET_KEY = "isi-dengan-kunci-acak-hasil-perintah-di-halaman-token"
alembic upgrade head
python buat_pengelola.py rina "sandi-rina-789"
fastapi dev main.py

    Urutannya penting:

    1. SECRET_KEY harus diisi sebelum server dijalankan (buat_pengelola.py tidak membutuhkannya). Cara membuat kunci ada di Token.
    2. alembic upgrade head membuat atau memperbarui tabel.
    3. buat_pengelola.py membuat akun pengelola pertama. Pendaftaran lewat API selalu menghasilkan anggota, jadi pengelola tidak bisa dibuat dari luar.

    Server berjalan di http://127.0.0.1:8000. Jika port 8000 dipakai aplikasi lain, tambahkan --port 8001 dan sesuaikan URL di bawah. Kata sandi sandi-rina-789 hanya contoh.

    from sqlmodel import Field, Relationship, SQLModel


# --- Pengguna ---------------------------------------------------------
class Pengguna(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    nama_pengguna: str = Field(unique=True, index=True, min_length=3, max_length=30)
    hash_kata_sandi: str
    peran: str = Field(default="anggota")  # "anggota" atau "pengelola"
    tugas: list["Tugas"] = Relationship(back_populates="pemilik")


class PenggunaBuat(SQLModel):
    nama_pengguna: str = Field(min_length=3, max_length=30)
    kata_sandi: str = Field(min_length=8, max_length=128)


class PenggunaPublik(SQLModel):
    id: int
    nama_pengguna: str
    peran: str


class Token(SQLModel):
    access_token: str
    token_type: str


# --- Kategori ---------------------------------------------------------
class KategoriDasar(SQLModel):
    nama: str = Field(min_length=2, max_length=50)


class Kategori(KategoriDasar, table=True):
    id: int | None = Field(default=None, primary_key=True)
    tugas: list["Tugas"] = Relationship(back_populates="kategori")


class KategoriBuat(KategoriDasar):
    pass


class KategoriPublik(KategoriDasar):
    id: int


# --- Tugas ------------------------------------------------------------
class TugasDasar(SQLModel):
    judul: str = Field(min_length=3, max_length=100)
    catatan: str | None = Field(default=None, max_length=500)
    prioritas: int = Field(default=2, ge=1, le=3, description="1 = tinggi, 3 = rendah")
    selesai: bool = False
    kategori_id: int | None = Field(default=None, foreign_key="kategori.id")


class Tugas(TugasDasar, table=True):
    id: int | None = Field(default=None, primary_key=True)
    pemilik_id: int | None = Field(default=None, foreign_key="pengguna.id")
    kategori: Kategori | None = Relationship(back_populates="tugas")
    pemilik: Pengguna | None = Relationship(back_populates="tugas")


class TugasBuat(TugasDasar):
    pass


class TugasUbah(SQLModel):
    judul: str | None = Field(default=None, min_length=3, max_length=100)
    catatan: str | None = Field(default=None, max_length=500)
    prioritas: int | None = Field(default=None, ge=1, le=3)
    selesai: bool | None = None
    kategori_id: int | None = None


class TugasPublik(TugasDasar):
    id: int
    pemilik_id: int | None = None


class TugasDenganKategori(TugasPublik):
    kategori: KategoriPublik | None = None

from jwt.exceptions import InvalidTokenError
from pwdlib import PasswordHash
from sqlmodel import Session, col, create_engine, select
from starlette.exceptions import HTTPException as StarletteHTTPException

from models import (

    KategoriBuat,
    KategoriPublik,
    Pengguna,

    Tugas,

# --- Konfigurasi ---------------------------------------------------------
SECRET_KEY = os.environ.get("SECRET_KEY")
if not SECRET_KEY:
    raise RuntimeError(
        "Variabel environment SECRET_KEY belum diisi. "
        'Buat kunci dengan: python -c "import secrets; print(secrets.token_hex(32))"'

ALGORITMA = "HS256"
MENIT_KEDALUWARSA = 30
ORIGIN_DIIZINKAN = ["http://localhost:3000"]

engine = create_engine("sqlite:///database.db", connect_args={"check_same_thread": False})

HASH_TIRUAN = password_hash.hash("kata-sandi-tiruan")
skema_oauth2 = OAuth2PasswordBearer(tokenUrl="token")

# Tabel dikelola Alembic: jalankan `alembic upgrade head` sebelum memulai server.

# --- Penanganan error (dari tahap 2 dan 3) -----------------------------------
class TugasTidakDitemukan(Exception):
    def __init__(self, tugas_id: int):
        self.tugas_id = tugas_id


class KategoriTidakDitemukan(Exception):
    def __init__(self, kategori_id: int):
        self.kategori_id = kategori_id


class JudulSudahAda(Exception):
    def __init__(self, judul: str):
        self.judul = judul


class NamaPenggunaSudahAda(Exception):
    def __init__(self, nama: str):
        self.nama = nama


def respons_galat(status_code: int, kode: str, pesan: str, rincian: list | None = None, headers: dict | None = None):
    isi = {"galat": {"kode": kode, "pesan": pesan, "rincian": rincian or []}}
    return JSONResponse(status_code=status_code, content=isi, headers=headers)


@app.exception_handler(TugasTidakDitemukan)
async def tugas_tidak_ditemukan_handler(request: Request, exc: TugasTidakDitemukan):
    return respons_galat(404, "TUGAS_TIDAK_ADA", f"Tugas dengan id {exc.tugas_id} tidak ditemukan")


@app.exception_handler(KategoriTidakDitemukan)
async def kategori_tidak_ditemukan_handler(request: Request, exc: KategoriTidakDitemukan):
    return respons_galat(404, "KATEGORI_TIDAK_ADA", f"Kategori dengan id {exc.kategori_id} tidak ditemukan")


@app.exception_handler(JudulSudahAda)
async def judul_sudah_ada_handler(request: Request, exc: JudulSudahAda):
    return respons_galat(409, "JUDUL_SUDAH_ADA", f"Judul '{exc.judul}' sudah dipakai")


@app.exception_handler(NamaPenggunaSudahAda)
async def nama_pengguna_sudah_ada_handler(request: Request, exc: NamaPenggunaSudahAda):
    return respons_galat(409, "NAMA_PENGGUNA_SUDAH_ADA", f"Nama pengguna '{exc.nama}' sudah dipakai")


@app.exception_handler(StarletteHTTPException)
async def http_exception_handler(request: Request, exc: StarletteHTTPException):
    return respons_galat(
        exc.status_code, f"HTTP_{exc.status_code}", str(exc.detail), headers=getattr(exc, "headers", None)
    )


@app.exception_handler(RequestValidationError)
async def validasi_handler(request: Request, exc: RequestValidationError):
    rincian = [
        {"field": ".".join(str(b) for b in galat["loc"]), "jenis": galat["type"], "pesan": galat["msg"]}
        for galat in exc.errors()
    ]
    return respons_galat(422, "VALIDASI_GAGAL", "Data yang dikirim tidak valid", rincian)


@app.exception_handler(Exception)
async def galat_tak_terduga_handler(request: Request, exc: Exception):
    return respons_galat(500, "GALAT_SERVER", "Terjadi kesalahan pada server")


# --- Session ------------------------------------------------------------------
def get_session():
    with Session(engine) as session:
        yield session


SessionDep = Annotated[Session, Depends(get_session)]
IdTugas = Annotated[int, Path(ge=1, title="ID tugas")]


# --- Autentikasi -----------------------------------------------------------------
def buat_token(nama_pengguna: str) -> str:
    isi = {"sub": nama_pengguna, "exp": datetime.now(timezone.utc) + timedelta(minutes=MENIT_KEDALUWARSA)}
    return jwt.encode(isi, SECRET_KEY, algorithm=ALGORITMA)


def pengguna_saat_ini(token: Annotated[str, Depends(skema_oauth2)], session: SessionDep) -> Pengguna:
    gagal = HTTPException(
        status_code=401,
        detail="Token tidak valid atau sudah kedaluwarsa",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        isi = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITMA])
    except InvalidTokenError:
        raise gagal
    nama = isi.get("sub")
    if not nama:
        raise gagal
    pengguna = session.exec(select(Pengguna).where(Pengguna.nama_pengguna == nama)).first()
    if pengguna is None:
        raise gagal
    return pengguna


PenggunaLogin = Annotated[Pengguna, Depends(pengguna_saat_ini)]


def wajib_pengelola(pengguna: PenggunaLogin) -> Pengguna:
    if pengguna.peran != "pengelola":
        raise HTTPException(status_code=403, detail="Hanya untuk pengelola")
    return pengguna


Pengelola = Annotated[Pengguna, Depends(wajib_pengelola)]


@app.post("/daftar", response_model=PenggunaPublik, status_code=status.HTTP_201_CREATED)
def daftar(data: PenggunaBuat, session: SessionDep):
    ada = session.exec(select(Pengguna).where(Pengguna.nama_pengguna == data.nama_pengguna)).first()
    if ada is not None:
        raise NamaPenggunaSudahAda(data.nama_pengguna)
    pengguna = Pengguna(
        nama_pengguna=data.nama_pengguna,
        hash_kata_sandi=password_hash.hash(data.kata_sandi),
        peran="anggota",
    )
    session.add(pengguna)
    session.commit()
    session.refresh(pengguna)
    return pengguna


@app.post("/token", response_model=Token)
def masuk(form: Annotated[OAuth2PasswordRequestForm, Depends()], session: SessionDep):
    pengguna = session.exec(select(Pengguna).where(Pengguna.nama_pengguna == form.username)).first()
    if pengguna is None:
        password_hash.verify(form.password, HASH_TIRUAN)  # samakan waktu respons
        sah = False
    else:
        sah = password_hash.verify(form.password, pengguna.hash_kata_sandi)
    if not sah:
        raise HTTPException(
            status_code=401,
            detail="Nama pengguna atau kata sandi salah",
            headers={"WWW-Authenticate": "Bearer"},
        )
    return Token(access_token=buat_token(pengguna.nama_pengguna), token_type="bearer")


@app.get("/saya", response_model=PenggunaPublik)
def profil_saya(pengguna: PenggunaLogin):
    return pengguna


# --- Fungsi pembantu data -------------------------------------------------------------
def pastikan_kategori_ada(session: Session, kategori_id: int | None) -> None:
    if kategori_id is not None and session.get(Kategori, kategori_id) is None:
        raise KategoriTidakDitemukan(kategori_id)


def pastikan_judul_unik(session: Session, pemilik_id: int | None, judul: str, abaikan_id: int | None = None) -> None:
    """Judul harus unik per pemilik, tanpa membedakan huruf besar-kecil."""
    pernyataan = select(Tugas).where(Tugas.pemilik_id == pemilik_id, col(Tugas.judul).ilike(judul))
    for tugas in session.exec(pernyataan).all():
        if tugas.id != abaikan_id:
            raise JudulSudahAda(judul)


def tugas_yang_boleh_diakses(tugas_id: IdTugas, pengguna: PenggunaLogin, session: SessionDep) -> Tugas:
    tugas = session.get(Tugas, tugas_id)
    if tugas is None:
        raise TugasTidakDitemukan(tugas_id)
    if tugas.pemilik_id != pengguna.id and pengguna.peran != "pengelola":
        raise HTTPException(status_code=403, detail="Tugas ini bukan milikmu")
    return tugas


TugasDiakses = Annotated[Tugas, Depends(tugas_yang_boleh_diakses)]

@app.get("/kategori", response_model=list[KategoriPublik])
def daftar_kategori(pengguna: PenggunaLogin, session: SessionDep):
    return session.exec(select(Kategori)).all()


# --- Tugas -----------------------------------------------------------------------------
@app.post("/tugas", response_model=TugasPublik, status_code=status.HTTP_201_CREATED)
def buat_tugas(data: TugasBuat, pengguna: PenggunaLogin, session: SessionDep):
    pastikan_kategori_ada(session, data.kategori_id)
    pastikan_judul_unik(session, pengguna.id, data.judul)
    tugas = Tugas.model_validate(data, update={"pemilik_id": pengguna.id})
    session.add(tugas)
    session.commit()
    session.refresh(tugas)
    return tugas


@app.get("/tugas", response_model=list[TugasPublik])
def daftar_tugas(
    pengguna: PenggunaLogin,
    session: SessionDep,
    selesai: bool | None = None,
    kategori_id: int | None = None,
    cari: Annotated[str | None, Query(min_length=2, max_length=50)] = None,
    offset: Annotated[int, Query(ge=0)] = 0,
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
):
    pernyataan = select(Tugas)
    if pengguna.peran != "pengelola":
        pernyataan = pernyataan.where(Tugas.pemilik_id == pengguna.id)
    if selesai is not None:
        pernyataan = pernyataan.where(Tugas.selesai == selesai)
    if kategori_id is not None:
        pernyataan = pernyataan.where(Tugas.kategori_id == kategori_id)
    if cari is not None:
        pernyataan = pernyataan.where(col(Tugas.judul).contains(cari))
    return session.exec(pernyataan.offset(offset).limit(limit)).all()


@app.get("/tugas/{tugas_id}", response_model=TugasDenganKategori)
def ambil_tugas(tugas: TugasDiakses):
    return tugas


@app.put("/tugas/{tugas_id}", response_model=TugasPublik)
def ganti_tugas(data: TugasBuat, tugas: TugasDiakses, session: SessionDep):
    pastikan_kategori_ada(session, data.kategori_id)
    pastikan_judul_unik(session, tugas.pemilik_id, data.judul, abaikan_id=tugas.id)
    tugas.sqlmodel_update(data.model_dump())
    session.add(tugas)
    session.commit()
    session.refresh(tugas)
    return tugas


@app.patch("/tugas/{tugas_id}", response_model=TugasPublik)
def ubah_tugas(data: TugasUbah, tugas: TugasDiakses, session: SessionDep):
    perubahan = data.model_dump(exclude_unset=True)
    for nama in ("judul", "prioritas", "selesai"):
        if nama in perubahan and perubahan[nama] is None:
            raise HTTPException(status_code=400, detail=f"Field '{nama}' tidak boleh null")
    if "judul" in perubahan:
        pastikan_judul_unik(session, tugas.pemilik_id, perubahan["judul"], abaikan_id=tugas.id)
    if "kategori_id" in perubahan:
        pastikan_kategori_ada(session, perubahan["kategori_id"])
    tugas.sqlmodel_update(perubahan)
    session.add(tugas)
    session.commit()
    session.refresh(tugas)
    return tugas


@app.delete("/tugas/{tugas_id}", status_code=status.HTTP_204_NO_CONTENT)
def hapus_tugas(tugas: TugasDiakses, session: SessionDep):
    session.delete(tugas)
    session.commit()

    buat_pengelola.py¶

    buat_pengelola.py
    """Membuat akun pengelola pertama. Jalankan sekali setelah `alembic upgrade head`.

Contoh:
    python buat_pengelola.py rina "kata-sandi-rina-123"
"""

import sys

from pwdlib import PasswordHash
from sqlmodel import Session, create_engine, select

from models import Pengguna

if len(sys.argv) != 3:

    Penjelasan kode¶

    Model¶

    • Pengguna adalah tabel baru: nama_pengguna (unik dan berindeks), hash_kata_sandi, dan peran. Kata sandi tidak pernah disimpan apa adanya.
    • PenggunaBuat adalah skema masuk (kata sandi), PenggunaPublik adalah skema keluar (tanpa hash), dan Token adalah respons login. Pola ini sama dengan Model dan Skema.
    • Tugas mendapat pemilik_id (foreign key ke pengguna.id) dan relasi pemilik. pemilik_id bersifat opsional agar tugas dari tahap 3 tetap valid.
    • TugasBuat tidak memuat pemilik_id, sehingga klien tidak bisa menentukannya. Hanya TugasPublik yang menampilkannya.

    Konfigurasi dan CORS¶

    SECRET_KEY dibaca dari environment; aplikasi menolak mulai bila kosong. CORSMiddleware hanya mengizinkan origin di ORIGIN_DIIZINKAN (di contoh, http://localhost:3000) dan method serta header yang dibutuhkan. Ingat dari CORS: ini mengatur apa yang boleh dibaca browser, bukan melindungi API; perlindungan datang dari autentikasi.

    Autentikasi¶

    • buat_token membuat JWT dengan sub berisi nama pengguna dan masa berlaku 30 menit.
    • pengguna_saat_ini memverifikasi token, lalu mencari pengguna di basis data lewat sub. Bedanya dengan halaman Proteksi Endpoint: penggunanya kini diambil dari tabel pengguna, dan dependency ini juga bergantung pada SessionDep. Semua kegagalan token dijawab satu 401.
    • /daftar menolak nama yang sudah ada (409), meng-hash kata sandi, dan selalu membuat peran anggota.
    • /token memverifikasi kata sandi dengan hash tiruan agar waktu respons seragam, seperti di Hashing Password.

    Otorisasi¶

    • wajib_pengelola menolak pengguna yang bukan pengelola dengan 403. Dipakai untuk membuat kategori.
    • tugas_yang_boleh_diakses mengambil tugas, menjawab 404 bila tidak ada, dan 403 bila pemanggil bukan pemilik dan bukan pengelola. Dipakai bersama oleh GET, PUT, PATCH, dan DELETE pada /tugas/{id}, sehingga aturan kepemilikan ditulis sekali.
    • daftar_tugas menyaring: anggota hanya melihat tugas dengan pemilik_id miliknya.
    • buat_tugas mengisi pemilik_id dari pengguna yang login (update={"pemilik_id": pengguna.id}), bukan dari body.
    • pastikan_judul_unik kini menerima pemilik_id, sehingga dua pengguna boleh punya tugas berjudul sama.

    Penanganan error¶

    Format {"galat": ...} dari tahap 2 dan 3 dipertahankan, dengan dua perubahan. Handler StarletteHTTPException kini meneruskan headers (agar WWW-Authenticate: Bearer ikut pada 401), dan ada exception baru NamaPenggunaSudahAda (409).

    Migrasi¶

    Revisi tahap 4 menambah tabel pengguna dan kolom pemilik_id beserta foreign key pada tugas. Hasil autogenerate perlu diperbaiki, dijelaskan di bagian berikutnya.

    Jebakan migrasi: foreign key di SQLite¶

    Revisi yang dihasilkan otomatis memakai op.add_column(...) lalu op.create_foreign_key(None, ...). Menjalankannya (alembic upgrade head) pada SQLite gagal:

    NotImplementedError: No support for ALTER of constraints in SQLite dialect. Please refer to the batch mode feature which allows for SQLite migrations using a copy-and-move strategy.

    Seperti jebakan di Migrasi, perubahan sebelum kegagalan sudah sempat diterapkan: tabel pengguna dan kolom pemilik_id tercipta, tetapi nomor revisi tidak berubah. Dalam percobaan, pemulihan dilakukan dengan membuat ulang basis data uji.

    Perbaikannya ada di berkas revisi final di atas:

    with op.batch_alter_table('tugas', schema=None) as batch_op:
    batch_op.add_column(sa.Column('pemilik_id', sa.Integer(), nullable=True))
    batch_op.create_foreign_key('fk_tugas_pemilik_id_pengguna', 'pengguna', ['pemilik_id'], ['id'])
    • batch_alter_table membuat salinan tabel dengan struktur baru, memindahkan datanya, lalu mengganti tabel lama (strategi copy-and-move yang disebut pada pesan galat).
    • Constraint diberi nama (fk_tugas_pemilik_id_pengguna). Hasil autogenerate memakai None, dan Alembic memperingatkan di downgrade bahwa nama None akan gagal.

    Hasil setelah perbaikan (basis data uji berisi satu tugas dari tahap 3):

    Keterbatasan tahap 4

    • Tidak ada kedaluwarsa atau pencabutan token selain masa berlaku 30 menit (dan hapus pengguna). Token tidak bisa dicabut seketika.
    • Tidak ada pembatasan percobaan login (rate limiting), pemulihan kata sandi, atau verifikasi email.
    • Peran hanya bisa diatur lewat skrip atau basis data, bukan lewat API.
    • Tugas tahap 3 yang tidak punya pemilik hanya dapat diakses pengelola; tidak ada alat untuk menetapkan pemiliknya.
    • Aplikasi belum dijalankan lewat HTTPS; token Bearer sebaiknya hanya dikirim lewat HTTPS pada aplikasi nyata.
    • CORS dan tombol Authorize di /docs belum diverifikasi lewat browser.
    • 500 belum diuji untuk proyek ini.

    Kesalahan umum¶

    Kesalahan Akibat

    Menjalankan server sebelum alembic upgrade head Tabel pengguna belum ada. Tidak dijalankan di sini; urutannya dijelaskan di atas.
    Memakai revisi autogenerate tanpa batch_alter_table untuk foreign key di SQLite NotImplementedError dan migrasi setengah jalan (teruji).
    Mengambil pemilik_id dari body Klien bisa membuat tugas atas nama orang lain. Ambil dari pengguna yang login.
    Mengembalikan semua tugas lalu menyaring di klien Data orang lain bocor. Saring di server (teruji pada GET /tugas).
    Membuat endpoint pembuat pengelola yang terbuka Siapa saja bisa menjadi pengelola. Pakai skrip yang dijalankan pemilik server.

    Latihan¶

    1. Dasar. Mengapa pendaftaran lewat API selalu menghasilkan anggota?
    2. Prediksi. Apa status sari membaca tugas 1 (tugas lama tanpa pemilik)? Mengapa?
    3. Migrasi. Mengapa revisi tahap 4 memakai batch_alter_table, dan apa yang terjadi bila tidak?
    4. Analisis. Mengapa keunikan judul sekarang per pemilik?
    Kunci jawaban

    Jawaban 2 sampai 4 mengacu pada hasil uji di atas. Jawaban 1 adalah penalaran dari kode.

    1. Agar pengguna tidak bisa menaikkan hak sendiri. Peran hanya ditetapkan oleh pemilik server lewat buat_pengelola.py atau langsung di basis data.
    2. 403 dengan Tugas ini bukan milikmu: pemilik_id tugas itu null, jadi bukan milik sari, dan sari bukan pengelola.
    3. SQLite tidak mendukung penambahan constraint lewat ALTER. Tanpa batch_alter_table, alembic upgrade head gagal dengan NotImplementedError: No support for ALTER of constraints in SQLite dialect dan meninggalkan basis data setengah jalan.
    4. Dua pengguna wajar punya tugas berjudul sama (teruji: sari berhasil membuat "belajar fastapi" padahal budi sudah punya). Keunikan global akan bocor informasi milik pengguna lain dan memaksa mereka mengubah judul.

    Ringkasan¶

    • Tahap 4 menambah pengguna, login berbasis token, dan kepemilikan data pada TugasKu API.
    • Kata sandi disimpan sebagai hash Argon2; respons tidak pernah memuat kata sandi maupun hash.
    • Semua endpoint tugas wajib login; pemilik_id diisi dari pengguna login, dan akses dibatasi pada pemilik atau pengelola.
    • Otorisasi peran (pengelola) dan kepemilikan memakai dependency yang ditulis sekali dan dipakai berulang.
    • Migrasi foreign key di SQLite butuh batch_alter_table dan nama constraint.
    • Kunci rahasia datang dari environment, dan CORS hanya mengizinkan origin frontend.
