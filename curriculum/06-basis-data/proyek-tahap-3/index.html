    Proyek Praktik Tahap 3¶

    Tujuan pembelajaran¶

    Setelah mengerjakan halaman ini, kamu mampu:

    • Memindahkan penyimpanan proyek dari memori ke basis data tanpa mengubah perilaku API.
    • Menyusun model tabel, skema input, dan skema output untuk Tugas dan Kategori.
    • Mengelola tabel dengan migrasi Alembic sejak awal proyek.
    • Mempertahankan format error terstruktur dari tahap 2.
    • Memastikan data bertahan setelah server dimulai ulang.

    Prasyarat¶

    • Sudah mengerjakan Proyek Praktik Tahap 2.
    • Sudah membaca seluruh materi Modul 06: Koneksi, Model dan Skema, Operasi CRUD, Relasi, dan Migrasi.

    Versi yang diuji

    Kode dan output di halaman ini dijalankan dengan Python 3.14.7, FastAPI 0.162.0, SQLModel 0.0.48, SQLAlchemy 2.1.6, dan Alembic 1.20.1 di Windows. Daftar versi lain ada di Versi yang dipakai di materi ini. Versi lain dan sistem operasi lain belum diuji.

    Tentang tahap ini¶

    Tahap 3 melanjutkan TugasKu API. Endpoint dan aturan dari tahap 2 dipertahankan; yang berubah adalah tempat data disimpan.

    Aspek Tahap 2 Tahap 3
    Penyimpanan dict di memori (hilang saat restart) SQLite lewat SQLModel
    Model satu set model Pydantic model tabel + skema input/output
    Struktur tabel tidak ada dikelola Alembic
    Relasi tidak ada Kategori satu-ke-banyak Tugas
    Format error {"galat": ...} sama, dengan tambahan KATEGORI_TIDAK_ADA
    Judul unik pemeriksaan di dict pemeriksaan lewat kueri, tidak peka huruf besar-kecil

    Kebutuhan¶

    Operasi Method dan path Sukses Kemungkinan error
    Buat kategori POST /kategori 201 422
    Daftar kategori GET /kategori 200
    Buat tugas POST /tugas 201 422, 404 kategori, 409 judul kembar
    Daftar tugas GET /tugas 200 422
    Ambil satu (dengan kategori) GET /tugas/{id} 200 404, 422
    Ganti PUT /tugas/{id} 200 404, 409, 422
    Ubah sebagian PATCH /tugas/{id} 200 400, 404, 409, 422
    Hapus DELETE /tugas/{id} 204 404, 422

    Struktur proyek¶

    Kode lengkap ada di examples/fastapi/proyek/tahap-3/:

    Berkas Fungsi
    models.py Model tabel dan skema
    main.py Aplikasi, penanganan error, dan endpoint
    alembic.ini, alembic/ Konfigurasi dan revisi migrasi

    Langkah menjalankan¶

    pip install "fastapi[standard]" sqlmodel alembic
alembic upgrade head
fastapi dev main.py

    Urutannya penting: alembic upgrade head sebelum server, karena aplikasi ini tidak membuat tabel sendiri. Server berjalan di http://127.0.0.1:8000. Jika port 8000 dipakai aplikasi lain, tambahkan --port 8001 dan sesuaikan URL di bawah.

    Kode lengkap¶

    models.py¶

    models.py
    from sqlmodel import Field, Relationship, SQLModel


# --- Kategori ---------------------------------------------------------
class KategoriDasar(SQLModel):
    nama: str = Field(min_length=2, max_length=50)


class Kategori(KategoriDasar, table=True):
    id: int | None = Field(default=None, primary_key=True)
    tugas: list["Tugas"] = Relationship(back_populates="kategori")


class KategoriBuat(KategoriDasar):
    pass


class KategoriPublik(KategoriDasar):
    id: int


# --- Tugas ------------------------------------------------------------
class TugasDasar(SQLModel):
    judul: str = Field(min_length=3, max_length=100)
    catatan: str | None = Field(default=None, max_length=500)
    prioritas: int = Field(default=2, ge=1, le=3, description="1 = tinggi, 3 = rendah")
    selesai: bool = False
    kategori_id: int | None = Field(default=None, foreign_key="kategori.id")


class Tugas(TugasDasar, table=True):
    id: int | None = Field(default=None, primary_key=True)
    kategori: Kategori | None = Relationship(back_populates="tugas")


class TugasBuat(TugasDasar):
    pass


class TugasUbah(SQLModel):
    judul: str | None = Field(default=None, min_length=3, max_length=100)
    catatan: str | None = Field(default=None, max_length=500)
    prioritas: int | None = Field(default=None, ge=1, le=3)
    selesai: bool | None = None
    kategori_id: int | None = None


class TugasPublik(TugasDasar):
    id: int


class TugasDenganKategori(TugasPublik):
    kategori: KategoriPublik | None = None

    main.py
    from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException, Path, Query, Request, status
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from sqlmodel import Session, col, create_engine, select
from starlette.exceptions import HTTPException as StarletteHTTPException

from models import (
    Kategori,
    KategoriBuat,
    KategoriPublik,
    Tugas,
    TugasBuat,
    TugasDenganKategori,
    TugasPublik,
    TugasUbah,
)

engine = create_engine("sqlite:///database.db", connect_args={"check_same_thread": False})

# Tabel dibuat dan diubah oleh Alembic: jalankan `alembic upgrade head` sebelum memulai server.

app = FastAPI(title="TugasKu API", description="Proyek praktik tahap 3: penyimpanan di basis data")


# --- Penanganan error (dari tahap 2) --------------------------------------
class TugasTidakDitemukan(Exception):
    def __init__(self, tugas_id: int):
        self.tugas_id = tugas_id


class KategoriTidakDitemukan(Exception):
    def __init__(self, kategori_id: int):
        self.kategori_id = kategori_id


class JudulSudahAda(Exception):
    def __init__(self, judul: str):
        self.judul = judul


def respons_galat(status_code: int, kode: str, pesan: str, rincian: list | None = None):
    isi = {"galat": {"kode": kode, "pesan": pesan, "rincian": rincian or []}}
    return JSONResponse(status_code=status_code, content=isi)


@app.exception_handler(TugasTidakDitemukan)
async def tugas_tidak_ditemukan_handler(request: Request, exc: TugasTidakDitemukan):
    return respons_galat(404, "TUGAS_TIDAK_ADA", f"Tugas dengan id {exc.tugas_id} tidak ditemukan")


@app.exception_handler(KategoriTidakDitemukan)
async def kategori_tidak_ditemukan_handler(request: Request, exc: KategoriTidakDitemukan):
    return respons_galat(404, "KATEGORI_TIDAK_ADA", f"Kategori dengan id {exc.kategori_id} tidak ditemukan")


@app.exception_handler(JudulSudahAda)
async def judul_sudah_ada_handler(request: Request, exc: JudulSudahAda):
    return respons_galat(409, "JUDUL_SUDAH_ADA", f"Judul '{exc.judul}' sudah dipakai")


@app.exception_handler(StarletteHTTPException)
async def http_exception_handler(request: Request, exc: StarletteHTTPException):
    return respons_galat(exc.status_code, f"HTTP_{exc.status_code}", str(exc.detail))


@app.exception_handler(RequestValidationError)
async def validasi_handler(request: Request, exc: RequestValidationError):
    rincian = [
        {"field": ".".join(str(b) for b in galat["loc"]), "jenis": galat["type"], "pesan": galat["msg"]}
        for galat in exc.errors()
    ]
    return respons_galat(
        status.HTTP_422_UNPROCESSABLE_CONTENT, "VALIDASI_GAGAL", "Data yang dikirim tidak valid", rincian
    )


@app.exception_handler(Exception)
async def galat_tak_terduga_handler(request: Request, exc: Exception):
    return respons_galat(500, "GALAT_SERVER", "Terjadi kesalahan pada server")


# --- Session dan fungsi pembantu --------------------------------------------
def get_session():
    with Session(engine) as session:
        yield session


SessionDep = Annotated[Session, Depends(get_session)]
IdTugas = Annotated[int, Path(ge=1, title="ID tugas")]


def cari_tugas(session: Session, tugas_id: int) -> Tugas:
    tugas = session.get(Tugas, tugas_id)
    if tugas is None:
        raise TugasTidakDitemukan(tugas_id)
    return tugas


def pastikan_kategori_ada(session: Session, kategori_id: int | None) -> None:
    if kategori_id is not None and session.get(Kategori, kategori_id) is None:
        raise KategoriTidakDitemukan(kategori_id)


def pastikan_judul_unik(session: Session, judul: str, abaikan_id: int | None = None) -> None:
    pernyataan = select(Tugas).where(col(Tugas.judul).ilike(judul))
    for tugas in session.exec(pernyataan).all():
        if tugas.id != abaikan_id:
            raise JudulSudahAda(judul)


# --- Kategori -------------------------------------------------------------
@app.post("/kategori", response_model=KategoriPublik, status_code=status.HTTP_201_CREATED)
def buat_kategori(data: KategoriBuat, session: SessionDep):
    kategori = Kategori.model_validate(data)
    session.add(kategori)
    session.commit()
    session.refresh(kategori)
    return kategori


@app.get("/kategori", response_model=list[KategoriPublik])
def daftar_kategori(session: SessionDep):
    return session.exec(select(Kategori)).all()


# --- Tugas ----------------------------------------------------------------
@app.post("/tugas", response_model=TugasPublik, status_code=status.HTTP_201_CREATED)
def buat_tugas(data: TugasBuat, session: SessionDep):
    pastikan_kategori_ada(session, data.kategori_id)
    pastikan_judul_unik(session, data.judul)
    tugas = Tugas.model_validate(data)
    session.add(tugas)
    session.commit()
    session.refresh(tugas)
    return tugas


@app.get("/tugas", response_model=list[TugasPublik])
def daftar_tugas(
    session: SessionDep,
    selesai: bool | None = None,
    kategori_id: int | None = None,
    cari: Annotated[str | None, Query(min_length=2, max_length=50)] = None,
    offset: Annotated[int, Query(ge=0)] = 0,
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
):
    pernyataan = select(Tugas)
    if selesai is not None:
        pernyataan = pernyataan.where(Tugas.selesai == selesai)
    if kategori_id is not None:
        pernyataan = pernyataan.where(Tugas.kategori_id == kategori_id)
    if cari is not None:
        pernyataan = pernyataan.where(col(Tugas.judul).contains(cari))
    return session.exec(pernyataan.offset(offset).limit(limit)).all()


@app.get("/tugas/{tugas_id}", response_model=TugasDenganKategori)
def ambil_tugas(tugas_id: IdTugas, session: SessionDep):
    return cari_tugas(session, tugas_id)


@app.put("/tugas/{tugas_id}", response_model=TugasPublik)
def ganti_tugas(tugas_id: IdTugas, data: TugasBuat, session: SessionDep):
    tugas = cari_tugas(session, tugas_id)
    pastikan_kategori_ada(session, data.kategori_id)
    pastikan_judul_unik(session, data.judul, abaikan_id=tugas_id)
    tugas.sqlmodel_update(data.model_dump())
    session.add(tugas)
    session.commit()
    session.refresh(tugas)
    return tugas


@app.patch("/tugas/{tugas_id}", response_model=TugasPublik)
def ubah_tugas(tugas_id: IdTugas, data: TugasUbah, session: SessionDep):
    tugas = cari_tugas(session, tugas_id)
    perubahan = data.model_dump(exclude_unset=True)
    for nama in ("judul", "prioritas", "selesai"):
        if nama in perubahan and perubahan[nama] is None:
            raise HTTPException(status_code=400, detail=f"Field '{nama}' tidak boleh null")
    if "judul" in perubahan:
        pastikan_judul_unik(session, perubahan["judul"], abaikan_id=tugas_id)
    if "kategori_id" in perubahan:
        pastikan_kategori_ada(session, perubahan["kategori_id"])
    tugas.sqlmodel_update(perubahan)
    session.add(tugas)
    session.commit()
    session.refresh(tugas)
    return tugas


@app.delete("/tugas/{tugas_id}", status_code=status.HTTP_204_NO_CONTENT)
def hapus_tugas(tugas_id: IdTugas, session: SessionDep):
    tugas = cari_tugas(session, tugas_id)
    session.delete(tugas)
    session.commit()

    Penjelasan kode¶

    Model dan skema¶

    Pola pewarisan dari Model dan Skema diterapkan pada dua entitas:

    • TugasDasar memuat field bersama beserta aturan validasi, dan kategori_id dengan foreign_key="kategori.id".
    • Tugas (table=True) menambah id dan atribut kategori (relasi).
    • TugasBuat, TugasUbah (semua field opsional), TugasPublik (menambah id), dan TugasDenganKategori (menyertakan objek kategori) adalah skema untuk input dan output.
    • Kategori mengikuti pola yang sama, dengan tugas: list["Tugas"] sebagai sisi lain relasi.

    Penanganan error¶

    Bagian exception dan handler dipindahkan dari tahap 2 dengan satu tambahan, KategoriTidakDitemukan (404), karena kategori_id kini harus merujuk kategori yang ada. Alasan pemeriksaan manual itu ada di Relasi: SQLite pada pengaturan ini tidak menolak kategori_id yang tidak ada.

    Session dan fungsi pembantu¶

    def get_session():
    with Session(engine) as session:
        yield session

    Dependency yield dari Dependency dengan yield: satu session per request, ditutup otomatis. Tiga fungsi pembantu mengelompokkan pemeriksaan yang dipakai berulang:

    • cari_tugas mengambil tugas atau melempar TugasTidakDitemukan.
    • pastikan_kategori_ada memeriksa kategori_id bila diisi.
    • pastikan_judul_unik mencari tugas dengan judul yang sama tanpa memperhatikan huruf besar-kecil (ilike). Parameter abaikan_id mencegah tugas dianggap bentrok dengan dirinya sendiri saat diubah.

    Endpoint¶

    • Buat: periksa kategori, periksa judul, baru simpan (add, commit, refresh). Pemeriksaan di depan agar tidak ada data berubah bila ada error.
    • Daftar: kueri select(Tugas) dirangkai dengan where untuk filter selesai, kategori_id, dan cari, lalu offset dan limit untuk paginasi.
    • Ambil satu: memakai TugasDenganKategori, sehingga respons menyertakan objek kategori.
    • Ganti (PUT): mengganti seluruh field dari TugasBuat.
    • Ubah sebagian (PATCH): model_dump(exclude_unset=True), menolak null untuk judul, prioritas, dan selesai dengan 400 (pelajaran dari temuan 500 di Operasi CRUD), lalu sqlmodel_update.
    • Hapus: session.delete lalu commit, dengan jawaban 204.

    Mengubah dan menghapus¶

    Request Status Isi
    PATCH /tugas/1 {"selesai":true,"catatan":null} 200 {"judul":"Belajar FastAPI","catatan":null,"prioritas":1,"selesai":true,"kategori_id":1,"id":1}
    GET /tugas?selesai=true 200 hanya tugas 1
    PATCH /tugas/1 {"judul":null} 400 {"galat":{"kode":"HTTP_400","pesan":"Field 'judul' tidak boleh null","rincian":[]}}
    PATCH /tugas/1 {"judul":"Cuci motor"} 409 JUDUL_SUDAH_ADA
    PATCH /tugas/1 {"kategori_id":99} 404 KATEGORI_TIDAK_ADA
    PUT /tugas/1 {"judul":"Belajar FastAPI lanjut","prioritas":1} 200 catatan dan selesai kembali ke nilai bawaan, kategori_id menjadi null
    DELETE /tugas/2 204 tanpa isi
    DELETE /tugas/2 (ulang) 404 TUGAS_TIDAK_ADA

    Perhatikan baris PUT: seperti di tahap 1, PUT mengganti seluruh data, jadi field yang tidak dikirim (catatan, kategori_id, selesai) kembali ke nilai bawaan. Di sinilah PATCH lebih aman untuk ubah sebagian.

    Data bertahan¶

    Setelah server dihentikan dan dijalankan lagi, data tetap ada. Diuji dengan menjalankan aplikasi baru pada basis data yang sama: GET /tugas mengembalikan tugas "Belajar FastAPI lanjut" dari sesi sebelumnya. Inilah perbedaan terpenting dengan tahap 1 dan 2.

    Keterbatasan tahap 3

    • Tidak ada pengguna atau login; siapa pun bisa mengubah dan menghapus (Modul 07).
    • Keunikan judul diperiksa oleh kode, bukan oleh basis data. Dua request bersamaan berpotensi sama-sama lolos pemeriksaan; ini penalaran, tidak diuji.
    • Kategori belum bisa diubah atau dihapus lewat API.
    • 500 belum diuji untuk proyek ini (handler Exception identik dengan Handler Error Kustom).
    • Tampilan Swagger UI belum diverifikasi lewat browser.

    Kesalahan umum¶

    Kesalahan Akibat
    Menjalankan server sebelum alembic upgrade head Tabel belum ada, sehingga permintaan ke basis data gagal. Tidak dijalankan di sini; urutan ini dijelaskan di atas.
    Menjalankan server dari folder yang berbeda database.db baru dibuat di folder itu, sehingga data lama tampak hilang.
    Mengubah model tanpa membuat revisi alembic check melaporkan New upgrade operations detected (teruji di Migrasi).
    Memakai model tabel sebagai body Tidak ada 422 yang andal; pakai TugasBuat dan TugasUbah.
    Menyimpan data lalu memeriksa error Periksa dulu, ubah belakangan.
    Mengirim database.db ke Git Berisi data; *.db diabaikan di .gitignore repositori ini.

    Latihan¶

    1. Dasar. Hentikan server, jalankan lagi, lalu GET /tugas. Apa yang kamu lihat dan mengapa?
    2. Endpoint baru. Tambahkan GET /kategori/{kategori_id} yang menyertakan daftar tugasnya, dan jawab 404 bila kategori tidak ada.
    3. Migrasi. Tambahkan kolom tenggat: str | None = None ke TugasDasar. Langkah apa saja yang perlu dilakukan agar tabel berubah tanpa menghapus data?
    4. Analisis. Mengapa pastikan_judul_unik dipanggil sebelum session.add?
    Kunci jawaban

    Jawaban 1 dan 2 dijalankan. Jawaban 3 mengacu pada alur yang teruji di Migrasi. Jawaban 4 adalah penalaran.

    1. Daftar tugas yang sama masih ada, karena data disimpan di berkas database.db, bukan di variabel.

    2. Teruji dengan TestClient:

      class KategoriDenganTugas(KategoriPublik):
    tugas: list[TugasPublik] = []


@app.get("/kategori/{kategori_id}", response_model=KategoriDenganTugas)
def ambil_kategori(kategori_id: int, session: SessionDep):
    kategori = session.get(Kategori, kategori_id)
    if kategori is None:
        raise KategoriTidakDitemukan(kategori_id)
    return kategori

      Hasil: GET /kategori/3 menghasilkan 200 dengan daftar tugas milik kategori itu, dan GET /kategori/99 menghasilkan 404 dengan KATEGORI_TIDAK_ADA.

    3. Tambahkan field di TugasDasar, jalankan alembic revision --autogenerate -m "tambah tenggat", baca berkas revisi (kolom nullable tidak perlu server_default), lalu alembic upgrade head. Cadangkan database.db sebelumnya.

    4. Agar tidak ada data yang tersimpan bila judul ternyata kembar. Memeriksa dulu menjaga basis data tetap konsisten saat terjadi error.

    Ringkasan¶

    • Tahap 3 memindahkan penyimpanan TugasKu API dari memori ke SQLite, tanpa mengubah kontrak API.
    • Model tabel, skema input, dan skema output dipisah; relasi Kategori ke Tugas ditambahkan.
    • Tabel dikelola oleh Alembic: alembic upgrade head dijalankan sebelum server.
    • Pemeriksaan keberadaan kategori dan keunikan judul dilakukan oleh kode, sebelum menyimpan.
    • Format error terstruktur dari tahap 2 tetap berlaku.
    • Data bertahan setelah server dimulai ulang.
